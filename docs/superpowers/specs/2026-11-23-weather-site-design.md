# 天氣預報網站 設計文件

日期：2026-11-23

## 要做什麼

一個公開的網站：使用者選一個縣市和鄉鎮，就能看到中央氣象署（舊稱中央氣象局）的天氣預報，加上離那個鄉鎮最近的觀測站實際量到的數字。

- 網頁放在 GitHub Pages，任何人打開網址就能用，不限公司網路。
- 氣象署的授權碼放在 Cloudflare Workers（放在 Cloudflare 主機上執行的小程式），網頁向它要資料，它再帶著授權碼去向氣象署取資料。
- 介面照 `ref/0001.png` 到 `ref/0009.png` 的排版和風格做。這 9 張是氣象署自己 App 的手機畫面。

使用者沒有特別說明網站的用途，只說會公開給別人用。

## 範圍

### 要做：預報（使用者選的 A 組）

- 主頁最上方：未來 24 小時最高和最低溫、天氣現象
- 三格小卡：降雨機率、紫外線、體感溫度
- 逐小時預報，點「詳細預報」打開 72 小時面板
- 生活建議：36 小時預報的三個時段各一張卡片
- 7 日預報，點「詳細預報」打開 7 日面板

### 要做：觀測和日出日落（使用者選的 B 組）

- 主頁最上方的大字溫度，用觀測站實際量到的溫度。風向、濕度也用實測值。
- 三格小卡：今天累積雨量、風速、氣壓（都是實測值）
- 日出、日落時間和太陽位置弧線

### 不做

- 空氣品質 AQI：資料來自環境部，要另外申請金鑰（使用者沒有選 C 組）
- 底部的「圖資」「警特報」分頁、右上角通知鈴鐺、廣告欄（使用者沒有選 D 組）
- 自動定位：要把經緯度換算成鄉鎮，需要另外的資料，使用者沒有要求
- 深色模式：參考圖裡沒有
- 國際都市預報

### 絕對不能發生

- 氣象署授權碼出現在網頁、瀏覽器看得到的網路請求、或公開的程式碼裡。
- 使用氣象署的標誌、App 名稱、App 裡的圖片，讓人以為這是官方網站。頁尾只寫「資料來源：中央氣象署」。
- 把預報值標成實際量到的數字，或反過來。畫面上每個數字是預報還是實測，要跟資料來源一致。

## 限制

- 氣象署 API：`https://opendata.cwa.gov.tw/api/v1/rest/datastore/{資料集編號}?Authorization={授權碼}`。完整欄位見 `https://opendata.cwa.gov.tw/apidoc/v1`（YAML 格式）。
- 「今明 36 小時預報」只有縣市層級，沒有鄉鎮層級。
- 鄉鎮預報是每個縣市各一組資料集，3 天預報和 1 週預報分開。
- 免費的 GitHub 帳號要把 repo 設為公開，才能用 GitHub Pages。
- Cloudflare Workers 免費方案每天 10 萬次請求。
- 開發環境：Windows 11、Node 24、npm 11、git、gh 都已安裝。
- 這台電腦有多個 gh 帳號。任何 `git push` 前先跑 `gh auth status`，確認目前帳號對目標 repo 有寫入權限；沒有的話先問使用者，不要自己切換。
- push 要經過公司 proxy。push 停住或出現 403 時，回報錯誤，不要一直重試。

## 考慮過的做法

| 做法 | 好處 | 代價 | 結果 |
|---|---|---|---|
| 1. 網頁放 GitHub Pages，授權碼放 Cloudflare Workers | 電腦不用開著；公司外面的人也能用；網址是 https | 要多註冊一個免費 Cloudflare 帳號 | **使用者選這個** |
| 2. 網頁放 GitHub Pages，伺服器放使用者電腦，用 Cloudflare Tunnel 讓外面連進來 | 伺服器在自己電腦上 | 電腦要一直開著；在公司電腦開放外部連入很可能違反資安規定 | 不採用 |
| 3. 網站和伺服器都放使用者電腦 | 不用任何外部帳號 | 只有公司網路裡的人打得開；GitHub Pages 上只能放一個連結 | 不採用 |
| 授權碼直接寫在網頁裡，網頁直接向氣象署要資料 | 最簡單 | 任何人都看得到授權碼 | 不採用，違反「絕對不能發生」第一條 |

使用者原本說伺服器架在自己電腦上，後來想把入口放在 GitHub Pages。GitHub Pages 是 https，瀏覽器不允許 https 網頁向 http 的伺服器要資料，而且公司外面的人連不到公司網路裡的電腦，所以改成做法 1。

## 使用者已經決定的

- 網站公開給別人用。
- 要有未來 36 小時、一週、鄉鎮層級的預報。
- 介面參考 `ref/` 底下的 9 張圖。
- 做 A 組（預報）和 B 組（觀測、日出日落），不做 C 組（空氣品質）和 D 組（圖資、警特報、通知、廣告）。
- 網頁放 GitHub Pages，授權碼放 Cloudflare Workers。
- 晚上打開時的顯示方式（見下方「晚上打開時」）。

## 晚上打開時

氣象署的預報只從「現在」開始往後算。晚上 6 點以後，36 小時預報和一週預報的第一段都是「今晚」，不再有「今天白天」。使用者決定這樣處理：

- **生活建議**：卡片名稱照資料實際涵蓋的時段標。早上是「今日白天、今晚明晨、明日白天」，晚上是「今晚明晨、明日白天、明日晚上」。名稱從每段的開始和結束時間算出來，不要寫死。
- **7 日預報**：「今天」那一列只顯示資料有的時段，晚上就只有晚上的預報。7 日面板的「每日預報」也一樣，今天只有「晚上」一段。
- **最上方的最高溫和最低溫**：用鄉鎮 3 天預報算「未來 24 小時」的最高和最低，標成「未來 24 小時 最高 26°・最低 17°」。任何時間打開都有資料，而且是預報值。
- **紫外線小卡**：顯示下一個白天的紫外線預報。這個白天是今天的話標「紫外線」，是明天的話標「明天紫外線」。

## 整體架構

```
瀏覽器
  │  打開網頁
  ▼
GitHub Pages（HTML、CSS、JS，沒有編譯步驟）
  │  fetch https://<worker 網址>/api/forecast?county=新北市&town=五股區
  ▼
Cloudflare Worker（授權碼存在 Worker 的 secret 裡）
  │  同時向氣象署要 5 份資料，整理成網頁要用的格式
  ▼
氣象署開放資料 API
```

### Worker 要向氣象署取的資料

| 用途 | 資料集 | 層級 |
|---|---|---|
| 生活建議（36 小時預報的三個時段） | F-C0032-001 今明 36 小時天氣預報 | 縣市 |
| 逐小時預報、72 小時面板、最上方的天氣現象和未來 24 小時最高最低溫、三格小卡的降雨機率和體感溫度 | F-D0047-0xx 該縣市未來 3 天 | 鄉鎮 |
| 7 日預報、7 日面板、紫外線 | F-D0047-0xx 該縣市未來 1 週 | 鄉鎮 |
| 實測溫度、濕度、風向、風速、氣壓、今天累積雨量 | O-A0001-001 全測站逐時氣象資料 | 測站 |
| 日出、日落 | A-B0062-001 日出日沒時刻 | 縣市 |

- 縣市對應到哪個 F-D0047 編號：從 API 文件每個資料集的 summary（例如「鄉鎮天氣預報-宜蘭縣未來3天天氣預報」）產生對照表，不要手打。
- 要用哪個觀測站：在 O-A0001-001 裡，找離所選鄉鎮最近、而且該項數值有效的測站。氣象署對缺值會填 `-99` 之類的數字，這些要當成沒有資料。不同項目可以來自不同測站（例如有些測站沒有氣壓），畫面上要寫出測站名稱。
- 鄉鎮的經緯度：預期 F-D0047 的回應裡有，要用真的授權碼確認。如果沒有，改成優先找同一個鄉鎮裡的測站，找不到再找同縣市的。

### Worker 的介面

- `GET /api/forecast?county=<縣市>&town=<鄉鎮>`：回傳一份整理好的 JSON，包含上面 5 份資料各自整理後的結果，以及每份資料的發布時間或觀測時間。
- 其中一份來源失敗時，其他部分照常回傳，失敗的部分標示為無法取得。網頁上那一塊顯示「暫時無法取得」，其他區塊照常顯示。
- 向氣象署取得的回應用 Cloudflare 的快取存起來，減少對氣象署的請求次數。建議預報 30 分鐘、觀測 10 分鐘、日出日落 1 天，實作者可以調整。
- CORS 只允許 GitHub Pages 的網址和本機開發用的網址。

### 縣市和鄉鎮清單

- 做成一個靜態 JSON 檔，跟網頁放在一起，不用每次向 Worker 要。
- 縣市和鄉鎮的寫法要跟氣象署一致（例如「臺北市」不是「台北市」），因為會直接當成查詢參數。
- 用一支一次性的腳本從氣象署的資料產生，腳本和產生的檔案都放進 repo。

## 畫面

整體：手機上照參考圖排列。電腦上把同樣的內容放在畫面中間一欄，寬度跟手機差不多，欄外是淺灰底。

### 主頁（參考 0001 到 0004）

由上往下：

1. **最上方**：左上是選單圖示，下面是「縣市 鄉鎮」名稱，點選單圖示或名稱都會打開地點選單。大字是實測溫度，下面一行是未來 24 小時最高和最低溫（預報），再來是天氣現象（預報），最後一行是風向和濕度（實測）。右側是淺藍色區塊加上天氣插圖，插圖隨天氣現象換成晴、多雲、陰、雨。往下捲動時，最上方縮成只有名稱、溫度、天氣的精簡版並固定在畫面頂端（參考 0002）。
2. **資料時間**：「觀測時間 09:00・上次更新 09:27」。
3. **三格小卡**：降雨機率（預報）、紫外線（下一個白天的預報，數值加等級，例如「5 中量級」；晚上標「明天紫外線」）、體感溫度（預報）。參考圖寫「近一小時降雨」，但鄉鎮預報的降雨機率是每 3 小時一筆，標籤照資料寫「降雨機率」。
4. **逐小時預報**：橫向捲動，每格是時間、天氣圖示、降雨機率、氣溫。第一格寫「現在」。右上「詳細預報 >」打開 72 小時面板。
5. **生活建議**：橫向捲動的卡片，36 小時預報的三個時段各一張，名稱照時段標（早上是今日白天、今晚明晨、明日白天；晚上是今晚明晨、明日白天、明日晚上）。每張有溫度範圍、降雨機率、舒適度文字，下方是建議圖示。圖示出現的規則（實作時以此為準，使用者可以再調整）：
   - 穿著：最高溫 26 度以上「短袖」；20 到 25 度「薄長袖」；15 到 19 度「外套」；15 度以下「厚外套」。
   - 降雨機率 50% 以上：「帶傘」。
   - 降雨機率 20% 以下，而且天氣現象沒有「雨」字：「適合曬衣」。
6. **7 日預報**：每天一列，有「今天／週二……」、日期、天氣圖示、降雨機率、最低溫到最高溫的橫條、紫外線、體感溫度最低和最高。橫條的位置和長度依整週的溫度範圍換算。晚上打開時，「今天」那一列只用晚上的預報。右上「詳細預報 >」打開 7 日面板。
7. **三格小卡**：今天累積雨量（mm）、風速（m/s）、氣壓（hPa），都是實測值，標出測站名稱。
8. **日出日落**：左邊日出時間、右邊日落時間，中間一條弧線，太陽圓點依現在時間放在弧線上。
9. **頁尾**：「資料來源：中央氣象署」。

### 72 小時面板（參考 0005、0006）

- 從畫面下方滑出，左上有關閉按鈕。
- 上方是日期列，只列出資料涵蓋到的日期。點日期，圖表捲到那一天。
- 分頁：氣溫、體感溫度、蒲福風級、濕度。參考圖寫「實際氣溫」，但這裡是預報值，為了不跟實測溫度混淆，改寫成「氣溫」。
- 分頁下方是選定時刻的數值和當天最高、最低，再下面是折線圖（平滑曲線、下方漸層填色）。
- 降雨機率是階梯狀的圖。
- 在圖上點選或拖動，可以選某個時刻，上方數值、風向、舒適度跟著變。

### 7 日面板（參考 0007、0008）

- 兩個分頁：每日預報、一週概況。
- 每日預報：上方日期列，選一天後顯示白天和晚上各一段（溫度範圍、降雨機率、濕度、蒲福風級、天氣文字和圖示），下面是體感最高、體感最低、紫外線三格。
- 一週概況：整週最高溫和最低溫兩條折線，下面四格：整週體感溫度最高值、整週體感溫度最低值、整週紫外線最高值、整週平均濕度。

### 地點選單

- 從畫面下方滑出，先選縣市，再選鄉鎮。
- 選過的地點存在瀏覽器（localStorage），下次打開直接顯示。第一次打開預設臺北市中正區。

### 視覺

- 白底，卡片淺灰底、圓角，大字溫度粗體。藍色用在降雨機率，橘色用在太陽和最高溫，藍色用在最低溫。顏色和間距照參考圖抓。
- 字型用系統字型（PingFang TC、Microsoft JhengHei、Noto Sans TC）。
- 天氣圖示用一套授權允許商用的開源圖示（例如 MIT 授權的 Meteocons），依氣象署天氣現象的代碼對應，分白天和晚上。不使用氣象署 App 裡的圖片。
- 最上方右側的天氣插圖自己畫，或把同一套圖示放大使用。

## 程式碼放哪裡

```
site/        網頁（HTML、CSS、JS），由 GitHub Actions 部署到 GitHub Pages
worker/      Cloudflare Worker 和它的測試
scripts/     一次性腳本（產生縣市鄉鎮清單等）
docs/        設計文件和計畫
ref/         參考圖
```

- 網頁不要放在 `docs/`，否則設計文件也會被公開在 GitHub Pages 上。
- 網頁沒有編譯步驟，直接用瀏覽器原生的 ES modules。
- Worker 的網址寫在 `site/` 裡的一個設定檔，本機開發時改成 `http://localhost:8787`。
- 授權碼：正式環境用 `wrangler secret put CWA_API_KEY`；本機開發放在 `worker/.dev.vars`，這個檔案要列進 `.gitignore`。

## 測試

- Worker 裡把氣象署資料整理成網頁格式的函式，用 Node 內建的 `node --test` 測試。測試資料是用真的授權碼抓下來的氣象署回應，存在 `worker/test/fixtures/`。早上（6 點到 18 點之間）和晚上（18 點以後）各抓一組。
- 測試要涵蓋：缺值（`-99`）的處理、找最近測站、其中一份來源失敗時其他部分照常回傳、預報和實測欄位沒有混在一起、早上和晚上的時段名稱和「今天」那一列都正確。

## 做完的樣子

- 用手機在公司網路外打開 GitHub Pages 網址，選新北市五股區，主頁 9 個區塊和兩個面板都顯示真實資料。白天和晚上 6 點以後各檢查一次。
- 在瀏覽器的原始碼和網路請求裡都找不到授權碼；公開的 repo 裡也找不到。
- `node --test` 全部通過。

## 需要使用者自己做的

1. 到 `https://opendata.cwa.gov.tw` 註冊並取得授權碼。
2. 註冊 Cloudflare 帳號，在這台電腦上執行 `npx wrangler login`（會打開瀏覽器登入）。
3. 決定用哪個 GitHub 帳號和 repo 名稱。

## 要用真的授權碼確認的事

- F-D0047 的回應裡有沒有鄉鎮的經緯度。
- 鄉鎮 3 天預報的氣溫是每小時一筆還是每 3 小時一筆。逐小時預報和 72 小時圖表照資料實際的間隔顯示。
- O-A0001-001 裡哪些測站有氣壓，今天累積雨量是哪個欄位。

## 留給實作者決定的

- 圖表用現成的函式庫（版本要固定）還是自己用 SVG 畫。
- 快取時間的實際數值。
- Worker 回傳的 JSON 欄位細節。
- 產生縣市鄉鎮清單的方式。
- 7 日預報列表裡，降雨機率多少以上才顯示。
- 天氣現象代碼和圖示的對應細節。
