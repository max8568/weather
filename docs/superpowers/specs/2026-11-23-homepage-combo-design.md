# 網站首頁改成組合版排法：設計

日期：2026-11-23
設計稿：`docs/weather-layout-claude/` 的「組合版」（`layouts/00-combo.js`、`layouts/00-combo.css`）
網站規格：`docs/superpowers/specs/2026-11-23-weather-site-design.md`

## 要做什麼、為什麼

使用者在原型裡反覆調整，定出了「組合版」這個首頁排法，現在要把網站首頁（`site/`）換成這個排法。資料照舊從 Worker API 來，原型只是設計稿，原型裡的假資料不放進網站。

做完後，用手機打開網站首頁，看到的排法、卡片樣式、字級要跟原型的組合版一樣；換地點、往下捲時的精簡列、「詳細預報」面板、載入中和錯誤畫面都照常能用。

## 目標

- 首頁由上往下依序是：溫度卡片、三格數字、逐小時預報、7 日預報、生活建議、目前觀測、日出日落、頁尾。
- 外觀照組合版（下面「已經決定的部分」逐區寫出）。
- 測站名稱和時間照使用者選的 B：放在頁尾「資料來源」上面；「目前觀測」每個數字下面寫自己的測站。

## 不做的事

- 不改 Worker、不改 API 的資料格式。
- 不改 72 小時面板、7 日面板、地點選單的內容和樣式（只會因為全站的卡片底色、線條顏色換值而跟著變一點點）。
- 不改往下捲時的精簡列（`#compact`）的樣子。
- 不動 `docs/weather-layout-claude/` 原型本身。

## 不能發生的事

- 實測值和預報值混在一起標錯。觀測溫度、濕度、風、累積雨量、氣壓是實測；其他是預報。
- 實測值的測站名稱從畫面上消失（網站規格：不同項目可以來自不同測站，畫面上要寫出測站名稱）。
- 缺值時拿別的數字補。缺值一律顯示 `--`（網站現有的 `deg`、`pct` 已經這樣做）。
- 換不了地點，或某一份資料抓不到時整頁空白。
- 把氣象署來的文字（測站名稱、天氣現象）用字串拼進 HTML。網站現在用 `h()` 建元素、用 `textContent` 放文字，維持這個做法。

## 限制

- 只用網站現有的技術：原生 ES module、不加套件、不加建置步驟。
- 手機寬度 320px 到 480px 都不能出現橫向捲軸；電腦上照舊是置中一欄。
- 測試用 `node --test`，網站的畫面程式沒有 DOM 可以測，所以能拆成純函式的邏輯（格式、顏色）放在 `site/js/logic/` 並寫測試；畫面用瀏覽器在 480、390、360、320px 寬量過。

## 做法

考慮過三種：

1. **直接改網站現有的畫面程式（使用者選這個）。** 改 `site/js/render/hero.js`、`site/js/render/sections.js`、`site/css/style.css`、`site/index.html`。換地點、精簡列、面板、錯誤畫面的程式繼續用。舊首頁的樣子留在 git 紀錄裡。
2. 把原型的程式複製到網站。原型用字串拼 HTML，氣象署的文字放進去有安全疑慮，網站也會有兩種畫畫面的寫法。沒選。
3. 另外做一頁 `site/combo.html` 跟首頁並存，確認後再換。可以用真資料比較新舊兩版，但多一次切換、之後還要刪舊程式。沒選。

## 已經決定的部分

數值以 `docs/weather-layout-claude/layouts/00-combo.css` 為準，下面列出重點。

### 全站

- 卡片樣式：淺灰底 `#f6f7f9`、1px 灰框 `#e2e5ea`、6px 圓角、內距 15px 12px。把 `:root` 的 `--card`、`--line` 換成這兩個值。
- 首頁左右內距 13px，各區之間隔 20px；溫度卡片和三格之間隔 8px。
- 每一區的標題放在卡片外面、卡片上方 8px：18px 粗體。逐小時預報、7 日預報的標題右邊有「詳細預報 >」（網站現有的 `.more` 按鈕），點了打開網站現有的 72 小時、7 日面板。
- 天氣圖示全部用 fill 樣式。

### 溫度卡片（`#hero`）

- 左右兩欄（右欄佔 30%），中間一條灰線，最小高度 200px。
- 左欄由上到下：地點（22px 粗體）、日期「11 月 23 日・星期一」（14px，日期取 `generatedAt`）、溫度（54px 粗體，數字後面接較小的「°C」，值是 `observation.temperature`）、「未來 24 小時 18°–24°」（14px，值是 `threeDay.next24h`）。
- 右欄：天氣圖示（寬度等於右欄），圖示正下方是天氣現象（17px 粗體，值是 `threeDay.current.weather`）。圖示依 `generatedAt` 分白天、晚上；沒有天氣現象時不放圖示，文字顯示 `--`。
- 溫度缺值時顯示「--°C」；未來 24 小時缺值時顯示「未來 24 小時 --°–--°」。
- 載入中、錯誤訊息和「重試」「選擇其他地點」按鈕照舊放在 `#hero` 裡，外觀是一般的溫度卡片框。
- 溫度卡片不標「實測」（使用者在原型裡的決定）。測站和觀測時間寫在頁尾。

### 三格數字（`#now`）

- 一排三格，白底、1px 灰框、6px 圓角，格子之間一條直線；名稱在上（13px）、數字在下（22px 粗體，單位 12px）。
- 順序：降雨機率（`threeDay.current.pop`）、體感溫度（`threeDay.current.apparentTemperature`，單位 °C）、紫外線（`weekly.uv`，數值加等級；名稱用 `weekly.uv.label`，晚上會是「明天紫外線」）。

### 逐小時預報（`#hourly`）

- 卡片裡一排可以左右捲的格子，每格由上到下：時間、天氣圖示（36px）、氣溫（16px）、降雨機率（12px 藍色）。
- 資料範圍照網站現在：`threeDay.hourly` 全部顯示。
- 時間標法照組合版：第一格「現在」，其他「18:00」，午夜那格寫日期「11/24」，而且那格左邊加一條直線。
- 網站現在的逐小時用 line 樣式圖示，再用 CSS `filter` 把雲變深；改用 fill 樣式後，這個 `filter` 拿掉。

### 7 日預報（`#weekly`）

- 每天一行：名稱（「今天／週二……」）、天氣圖示（32px）、降雨機率（12px 藍色，靠右）、最低溫、溫度條、最高溫。
- 最低溫、最高溫固定在左右兩欄（各 30px、15px 粗體），七天的數字上下對齊。
- 溫度條：6px 高、3px 圓角，灰色底線代表整週最低溫到最高溫，彩色段的位置和長度照 `tempBar` 換算。
- 溫度條顏色用固定色階：0° `#5f84ba`、16° `#8cc1f2`、20° `#f3aa94`、40° `#ca6360`，中間照比例混色；彩色段標出兩端和中間經過的色階點（原型 `parts.js` 的 `tempColor`、`tempGradient`）。
- 最低溫跟降雨機率之間至少 24px。
- 7 日預報不顯示日期、紫外線、體感（使用者在原型裡選「只學溫度那段、每天一行」）。這些在 7 日面板裡還看得到。

### 生活建議（`#advice`）

- 外面沒有卡片，標題下面直接一排可以左右捲的卡片，左右捲時可以捲到螢幕邊。
- 每張卡片的內容和排法照網站現在的（上半時段、溫度、降雨，右邊圖示和舒適度；下半一排建議圖示），卡片樣式換成全站的灰底灰框 6px 圓角，寬度 86%。

### 目前觀測（`#obs`）

- 標題「目前觀測」，右邊副標題「實測 16:00」（`observation.time`）。
- 卡片裡三欄：濕度、風速、風向、氣壓、今天累積雨量；名稱 12px、數字 18px 粗體、單位 12px。
- 每個數字下面寫它的測站「五股測站」（11px）。缺值時數字顯示 `--`，不寫測站。

### 日出日落（`#sun`）

- 加上卡片外的標題「日出日落」。卡片內容照網站現在的（兩端圖示和時間、中間弧線、太陽圓點）。

### 頁尾

- 「資料來源：中央氣象署」上面放網站現有的資料時間那一行（`renderDataTime`：溫度、風向、濕度的測站名稱、觀測時間、上次更新），內容不變，只換位置；跟頁尾一樣置中。
- `index.html` 的順序：`#hero`、`#now`、`#hourly`、`#weekly`、`#advice`、`#obs`、`#sun`、`#data-time`、頁尾。

## 要寫的測試

- `site/js/logic/format.js` 新增 `tempColor(t)`、`tempGradient(min, max)`：0° 到 15° 偏藍、21° 到 40° 偏紅，每個顏色的相對亮度至少 0.2，漸層裡每個顏色點都等於那個溫度在色階上的顏色（照原型的測試寫）。
- `hourLabel` 改成「18:00」的格式，原本的測試跟著改。
- 溫度卡片的日期文字抽成純函式，例如 `dateLabel('2026-11-23T16:10:00+08:00')` 回傳「11 月 23 日・星期一」，跨月、跨年各測一次。

## 留給實作的人決定

- `sections.js` 裡要不要把 `sectionHead` 改成接受副標題，或另外寫一個。
- 原型的 `tempColor`、`tempGradient` 改寫成 `site/js/logic/format.js` 的函式時的寫法。
- CSS 要不要整理掉用不到的舊規則（例如舊的溫度區塊天藍色面板，精簡列還在用的要留著）。

## 我自己決定的部分（使用者可以改）

- **換地點：** 地點文字做成按鈕，左邊放網站現有的選單圖示，兩個都打開地點選單（網站規格要求「點選單圖示或名稱都會打開地點選單」）。
- **逐小時的資料範圍：** 原型只放 24 小時，網站現在把 `threeDay.hourly` 全部放進去；照網站現在，因為少放的部分本來就在使用者手機上看得到，改少會讓人以為資料不見。
- **逐小時的時間標法：** 改成組合版的「18:00」（網站現在是「18時」），`hourLabel` 跟著改、測試跟著改。
- **7 日預報的降雨機率：** 網站現在低於 30% 不顯示，組合版每天都顯示；照組合版每天都顯示。
- **「今天累積雨量」：** 原型寫「今日累積雨量」，照網站規格和網站現在的寫法用「今天」。
- **`--card`、`--line` 全站換值：** 面板裡的小卡和線條也會跟著變成新的灰色，差別很小，換成同一組顏色比較一致。
